# TestForge

Десктопное GUI-приложение для автоматизированного тестирования веб-сайтов, API и Windows-приложений. 
Личный pet-проект для практики Python и изучения автотестирования.

## Возможности

### Веб-тестирование (Playwright)
- Проверка доступности страницы и непустого заголовка
- Поиск заданного текста на странице
- Проверка видимости элемента по CSS-селектору
- Проверка времени загрузки страницы
- Поиск ошибок в консоли браузера
- Проверка битых ссылок на странице
- Сценарии действий (`fill`, `click`) — заполнение форм, клики, многошаговые сценарии (например, логин)

### API-тестирование (requests)
- Поддержка методов GET, POST, PUT, DELETE с телом запроса
- Пользовательские заголовки, включая авторизацию (Bearer-токены)
- Проверка статус-кода (диапазон 200–299)
- Проверка валидности JSON-ответа
- Проверка Content-Type
- Проверка обязательных полей в ответе (упрощённая schema validation)
- Проверка времени ответа
- Понятная обработка сетевых ошибок и невалидного JSON

### Desktop-тестирование (pywinauto)
- Запуск произвольного `.exe` и проверка появления окна
- Проверка времени запуска приложения
- Проверка текста в окне
- Проверка видимости именованного элемента
- Сценарии действий (`click`, `type`)

> Видимость элементов и сценарии надёжно работают на классических win32-приложениях. 
> Современные системные утилиты Windows 11 (Калькулятор, Блокнот), использующие UWP/MSIX 
> или WinUI, поддерживают только базовые проверки (запуск, время, текст в заголовке).

### Отчёты и логирование
- Allure Report — интерактивные HTML-отчёты с шагами, вложениями и историей прогонов
- Скриншоты и тексты ответов при падении тестов
- Логирование всех прогонов в `logs/testforge.log`
- Автоочистка логов старше 30 дней, ручная очистка с архивацией

## Стек

- Python 3.11+
- PyQt6 — графический интерфейс
- pytest — тестовый раннер
- Playwright — веб-автоматизация
- pywinauto — desktop-автоматизация
- requests — HTTP-запросы
- Allure — отчётность

## Установка

```bash
git clone https://github.com/Kazmech-cmd/TestForge.git
cd TestForge
python -m pip install -r requirements.txt
python -m playwright install chromium
```

Для отчётов дополнительно нужны Java и [Allure Commandline](https://github.com/allure-framework/allure2/releases) 
(добавить папку `bin` из архива в PATH).

## Запуск

```bash
python gui/main_window.py
```

## Сборка .exe

```bash
python -m PyInstaller --onefile --windowed --icon=assets/testforge.ico --add-data "tests;tests" --add-data "assets;assets" --name TestForge gui/main_window.py
```

## Ограничения desktop-тестов

Desktop-тестирование использует pywinauto (win32-бэкенд). Базовые проверки — запуск приложения, 
время старта, текст в заголовке окна — работают надёжно на любом `.exe`.

Проверки "видимость элемента" и "сценарий действий" (click/type) рассчитаны на классические 
win32-приложения (сторонний софт, старые корпоративные программы, WinForms/MFC-приложения). 
Современные системные утилиты Windows 11 (Калькулятор, Блокнот) всё чаще используют 
UWP/MSIX-упаковку или WinUI/XAML, которые win32-бэкенд не видит на уровне отдельных элементов — 
на них будет работать только базовый набор проверок.
